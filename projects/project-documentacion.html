Documentación Técnica y Automatización

Diseño, análisis y documentación de soluciones reales basadas en automatización

Este proyecto reúne la documentación técnica de distintas soluciones reales de automatización desarrolladas en contextos diferentes, aplicando una metodología común de análisis, diseño e implementación.

El objetivo no es solo mostrar el resultado final, sino explicar el proceso completo: desde la detección del problema hasta la solución técnica, facilitando la comprensión, el mantenimiento y la escalabilidad de cada sistema.

La documentación está pensada tanto para perfiles técnicos como no técnicos, priorizando la claridad, la estructura y la trazabilidad de cada flujo.

Caso Principal · Yugidex

Bloque 1: Explicación y Origen

Origen del proyecto

Yugidex nace a partir de una necesidad real dentro del mundo del coleccionismo de cartas. Tras una conversación con un amigo, se detectó un problema común: la mayoría de aplicaciones existentes ofrecen catálogos completos de cartas, pero no están enfocadas en responder a una pregunta clave para coleccionistas y tiendas:

"¿Qué cartas tengo exactamente en mi colección?"

Problema del coleccionista

Las soluciones actuales obligan al usuario a crear decks manualmente o a consultar bases de datos oficiales, lo que resulta poco práctico cuando se trabaja con grandes volúmenes de cartas. La introducción manual de datos es viable para unas pocas cartas, pero se vuelve inviable cuando se trata de cientos o miles, llegando incluso a colecciones de decenas de miles de unidades.

Yugidex surge como respuesta a esa necesidad: catalogar cartas de forma rápida, eficiente y sin fricción, eliminando la carga del trabajo manual.

Usuario objetivo

Yugidex está orientado principalmente a:

Coleccionistas

Que necesitan tener un control claro y real de su colección.

Tenderos

Que requieren gestionar inventarios de cartas de forma rápida y fiable.

La aplicación está diseñada como una solución escalable, pensada para crecer y evolucionar con nuevas funcionalidades. Actualmente se encuentra en fase MVP completamente funcional, con múltiples mejoras planificadas a corto y medio plazo.

Estado actual del proyecto

En su estado actual, Yugidex permite:

  • Escanear cartas físicas mediante la cámara del dispositivo.
  • Identificar automáticamente cada carta.
  • Almacenar las cartas en una base de datos propia del usuario.
  • Consultar y gestionar la colección (visualización y eliminación).
  • Crear y editar decks personalizados.

Todo el flujo está optimizado para reducir al mínimo la intervención manual del usuario.

Propuesta de valor

El principal valor de Yugidex es el ahorro masivo de tiempo.

Datos automáticos

Los datos de las cartas se obtienen automáticamente desde una API externa.

Sin intervención manual

El usuario no introduce información manualmente.

Sistema retroalimentado

La base de datos no parte de un catálogo cerrado, sino que crece en función de las cartas reales de los usuarios.

Este enfoque evita:

  • Mantener bases de datos gigantescas desde el inicio.
  • Duplicar información innecesaria.
  • Invertir tiempo en tareas repetitivas.

En la práctica, el tiempo necesario para introducir una carta manualmente equivale al tiempo que Yugidex necesita para catalogar decenas o cientos mediante escaneo, lo que marca una diferencia crítica en proyectos de gran escala.

Bloque 2: Arquitectura del Sistema

Visión general

Yugidex está construido sobre una arquitectura distribuida, donde cada componente cumple una función clara y especializada, permitiendo escalar el sistema y mantenerlo fácilmente a largo plazo.

El sistema se compone de cuatro piezas principales:

Diagrama de arquitectura

Aplicación móvil

La app móvil es el punto de entrada principal del usuario. Desde ella se gestiona todo el flujo relacionado con el escaneo y la interacción directa con la colección:

  • Escaneo de cartas mediante OCR.
  • Extracción y envío de los códigos identificados.
  • Consulta de los datos almacenados.
  • Gestión de la colección personal (visualización, eliminación).
  • Creación y edición de decks.

La aplicación no almacena datos complejos ni lógica pesada, sino que actúa como interfaz y orquestador de acciones, delegando los procesos intensivos al backend.

Aplicación web (CRM)

La versión web funciona como un CRM de gestión, compartiendo la misma base de datos que la app móvil pero sin funcionalidades de escaneo.

Desde el CRM se permite:

  • Gestión completa de cartas y decks.
  • Visualización y edición de datos almacenados en Supabase.
  • Análisis de la colección (cantidad de cartas, distribución, etc.).

Esto permite separar claramente el uso móvil (captura y consulta rápida) del uso web (gestión y análisis).

Automatizaciones con n8n

n8n actúa como el núcleo lógico del sistema. Es el encargado de:

  • Recibir los códigos de cartas escaneadas desde la app.
  • Comprobar si la carta ya existe en la base de datos.
  • Consultar la API de Yugipedia cuando es necesario.
  • Normalizar, validar y almacenar los datos.
  • Garantizar la coherencia y actualización progresiva de la base de datos.

Toda la lógica de validación, enriquecimiento de datos y control de duplicados reside aquí, manteniendo las aplicaciones ligeras y desacopladas.

Flujo de automatización n8n

Base de datos y servicios externos

Supabase

Se utiliza como base de datos central, almacenando cartas, usuarios, colecciones y decks.

API de Yugipedia

Se emplea como fuente externa de información para obtener los datos oficiales de cada carta cuando aún no existen en el sistema.

Este enfoque permite que la base de datos crezca de forma orgánica, alimentada por el uso real de los usuarios, evitando mantener catálogos completos innecesariamente grandes.

Bloque 3: Flujo de Funcionamiento (End-to-End)

Visión general del flujo

El flujo completo de Yugidex está diseñado para que el usuario pueda catalogar grandes volúmenes de cartas de forma rápida y sin intervención manual.

1. Escaneo desde la app móvil

El usuario inicia el proceso desde la aplicación móvil escaneando una o varias cartas. Durante este proceso:

  • Se detecta el código único de cada carta mediante OCR.
  • Se valida el formato del código.
  • Se agrupan los códigos escaneados.

Una vez finalizado el escaneo, la app muestra una pantalla de progreso mientras se envían los datos.

Proceso de escaneo OCR

2. Envío de datos a n8n

Los códigos detectados se envían a un workflow de n8n mediante un webhook.

A partir de aquí:

  • La app queda a la espera.
  • Todo el procesamiento se traslada al backend.

3. Procesamiento y validación en n8n

n8n recibe los códigos y ejecuta una serie de pasos automatizados:

  • Comprobación de existencia de la carta en Supabase.
  • Si no existe, consulta a la API de Yugipedia.
  • Normalización de datos (nombre, atributos, imagen, estadísticas).
  • Inserción o actualización en la base de datos.
  • Asociación de la carta al usuario correspondiente.

Este sistema evita duplicados y mantiene los datos coherentes.

Validación y normalización de datos

4. Respuesta y sincronización

Una vez terminado el proceso:

  • n8n devuelve la confirmación.
  • La app consulta Supabase.
  • Se muestran inmediatamente las cartas añadidas al usuario.

Todo el proceso ocurre sin que el usuario tenga que introducir ningún dato manualmente.

5. Gestión posterior

A partir de ese momento, el usuario puede:

  • Consultar su colección.
  • Eliminar cartas.
  • Crear y editar decks.
  • Analizar su inventario.

La aplicación web ofrece las mismas capacidades de gestión, enfocadas a uso administrativo y análisis.
